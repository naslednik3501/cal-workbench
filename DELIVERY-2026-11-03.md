# Calculator delivery — 3 November 2026

Sportage 95160 is included unchanged in the working catalog (PR #3). The follow-up
release consolidates exact CAL duplicates, restores original illustrations, and
improves binary/text execution without inventing missing instructions.

## Visible changes

- 23,357 archived CAL entries become 15,057 visible content variants. All 8,300
  exact duplicate instances retain their original paths, search aliases and source
  selection. Equal names with different contents stay separate.
- 135 original images restore 623 missing reference occurrences across 288 unique
  CALs. Board pictures keep their aspect ratio and fit the form; logos are compact.
  Images load when the relevant form is opened. Exact source/control bindings and
  image provenance are in `IMAGE-RESTORATION.md` and its linked files.
- Binary handlers are validated individually. A valid reader can open when its
  writer fails, but the original failure is retained and attempting the writer
  throws. No unknown opcode is skipped, address rewritten or return invented.
- The UI labels every partial program «Только чтение», disables calculation and
  selection actions, and never exposes OnShow preparation as a downloadable
  result. Independent manual HEX editing still starts from the original BIN.
- 18 explicitly identified text originals have one surplus final brace removed
  only in the parsing view. SHA-specific profiles also check length/CRC; the
  archived CAL bytes and export remain unchanged. Arbitrary malformed sources
  are still rejected. These 18 were executed on zero, FF and patterned synthetic
  buffers; Subaru complement/readback and Mitsubishi key placement have separate
  expected-byte checks.
- `.mismatch` is a bounded transactional byte annotation, separate from data.
  Three originals that become parseable through it have inconsistent writers:
  Audi does not update the login copy checked on reopening; two Hyundai sources
  have an unresolved shift expression. Their writers stay blocked with a reason.

## Current coverage, not a claim of correct results on every real dump

| State | Distinct CAL contents | Archived CAL entries |
|---|---:|---:|
| All referenced handlers recognized | 14,712 | 22,933 |
| Partial; application permits reading only | 257 | 293 |
| Unavailable | 88 | 131 |
| Total | 15,057 | 23,357 |

The 257 partial versions comprise 254 binary originals and three text originals.
The remaining 88 comprise 16 binary validation failures, 60 text parsing failures
and 12 other/unrecognized formats. Four FIS versions can read their forms but
still cannot execute opcode 0x4D. All paths/reasons are reproducible with
`node tools/audit-calculators.js reports/calculator-coverage-2026-11-03.json`.
No current calculator or resource was globally deleted by hardware classification;
that review remains incomplete. The ordinary calculator list already excludes
non-CAL files. Missing images remain 1,714 reference occurrences, including 154
empty picture controls; these counts do not measure broken algorithms.

The source inventory found 15,056 distinct direct CAL contents in the five source
indexes; the only one missing before this delivery was Sportage. The application
also includes the previously extracted nested-RAR Polo. Thus the known direct CAL
inventory is present; this does not prove every nested container has useful CALs.

## Verification

Portable checks cover catalog payload hashes, alias grouping, scope policy,
transaction rollback, bounded source annotations/repairs, independent Sportage
and Polo formulas, storage and original preservation. The 465 existing text/binary
pairs still yield 456 exact matches, four byte differences and six control
differences across nine pairs, with no execution errors. These known differences
are not silently changed by this release.

Chromium checks cover real catalog alias search/selection, repeated imports,
IndexedDB reload, synthetic BIN preparation and downloads, built-in Sportage
against an independent full-buffer expected result, partial readers, and original
image decoding/layout. `tests/test_release_browser.js` is the release integration
check; browser tests accept a localhost URL and `CHROMIUM_EXECUTABLE_PATH`.

These tests use synthetic BINs. Original iProg comparison, physical blocks and
Windows browser verification are not claimed. The remaining failures require
specific decoder/algorithm evidence or a complete original source, not blanket
error suppression.
