# CAL Workbench 0.1 — development checkpoint

This directory is a standalone offline prototype reconstructed during the continuation turn. Prior chat messages describe a larger prototype and a full audit, but neither its source nor the four full archives was present in the current workspace. Do not confuse those historical statements with this build's evidence.

## Available inputs and preservation

- `upload/Calculators.zip` was available. The package contains 23,944 entries, including 23,355 CAL entries / 15,055 unique CAL byte contents.
- All non-directory, non-`__MACOSX` entries are preserved in `catalog.js` + `catalog-data/*.js`. Every path has its own entry. Identical byte payloads share a blob; no duplicate CAL entry was removed.
- 8,300 repeated CAL instances remain visible. All content hashes are verified in `tests/test_catalog.js`.
- Four full archives and the former 24,814-CAL index are unavailable. No Library search or undeclared file access was used to recover them.

## Architecture

- Plain local HTML/CSS/classic JavaScript, no build-time dependencies for users, no server, network calls, eval, hardware access or native code execution.
- `engine.js`: checksum-verified CAL decoder, form parser, reachable-code validator, transactional bytecode runtime.
- `app.js`: lazy folder tree, search with pagination, BIN import/hash, script forms, preview/diff, download copy/report, manual byte edit, directory/CAL import.
- Separate data chunks avoid oversized script files and make packaging reproducible.
- Decoder format reference: the available local `iprog-analysis` project, whose Git origin is `https://github.com/ivanus0/iProg-script-disasm.git`. The runtime is independently written for this prototype. Original upstream EXE/script files are preserved as data, never executed.

## Confirmed and unconfirmed

14 runtime regression/error tests PASS in Node 24.22.1. Real supplied RAV4 and Mitsubishi dumps match previous CAL outputs; VW matches the five literal ranges in its supplied listing. Decoded bytes agree with fixtures generated by the independent Python decoder. These are algorithm checks, not real-vehicle safety validation.

Static audit: 21,549 entries parsed/executable under the implemented subset, 4 with unsupported instructions, 1,802 other parse/format failures. All reachable paths are validated before execution. Unknown operations are rejected rather than skipped. `static-audit.json` records per-entry outcomes.

Arithmetic assumptions (unsigned 32-bit, masked shift count, hex/decimal formatting and zero-based combo indexes) are not exhaustively verified against original iProg. The loop, arithmetic and numeric input tests are synthetic; checksum/VIN algorithms still need independent real reference outputs. Keep this limitation explicit.

Browser integration test is included but NOT executed successfully: Playwright is installed but its Chromium executable is absent. Windows 11 execution and visual UI inspection remain unverified. There is no native .exe package. Do not claim browser or Windows testing passed.

Private fixture comparisons are development regression checks; they are not a list of confirmed application defects.

# Version 0.3 update — 2026-11-01

User imports now go through `catalog-store.js`: validated CAL/image records are saved to IndexedDB in atomic transactions, loaded on startup, and exportable/importable as JSON `.calpack` files. No user BIN is persisted. Missing/denied/full storage leaves imports in memory with an explicit temporary-session warning, never a false saved state. Imports are limited to 200 MiB / 30,000 records. Export SHA-256 values are verified on import where WebCrypto is available. Exact filename duplicates retain separate UUIDs. Re-importing a package adds entries rather than deleting/replacing existing ones. This is not automatic multi-user synchronization.

Because `file:` storage behavior is browser-specific, same-browser/profile usage and regular .calpack backups are documented. A shared online catalog would require a stable hosted origin, server storage, authentication, and publication roles; no such deployment was requested or performed.

The catalog displays root sections without the `Calculators/` wrapper while retaining canonical stored paths. Entering a root section scopes the view to that section. Navigation context and Back remain outside the scroll area. Search stays global; collapse-all returns to roots. Import controls moved into the catalog panel, with destination selection and a separate last-sorted My Calculators section.

BIN close invalidates in-flight load generations, clears original/candidate/session/hash/selection, and keeps selected CAL. HEX cells support selection, Shift range, right-column double-click editing (Enter commit, Escape cancel), with unchanged left-hand originals. All editing remains in the working copy.

Check button renamed `Прочитать данные`: it calls CAL OnShow on a separate VM for candidate/original without mutation. CAL information groups are titled `Сообщение калькулятора`. Calculator messages are script output and must not be treated as an engine-generated compatibility verdict.

Engine.js remains unchanged. Full re-read of Calculators.zip including CRC checks, paths, sizes and SHA-256 matches all 23,944 included entries / 23,355 CALs. Static subset audit remains 21,549 parsed / 4 unsupported commands / 1,802 other format or parse failures. No full compatibility claims.

Missing archives in this workspace: Архив.zip, Архив 4.zip, Архив 2.zip, Архив(1).zip. These must be reattached before their formats/resources can be examined. The earlier 41,874-file full audit is historical and cannot be revalidated without those inputs.

Tests: 15 engine regressions, 20 application state/event tests, 8 store/serialization/transaction tests, catalog hashes and archive identity checks. App/store tests use Node adapters, not real-browser DOM/IndexedDB. Existing browser policy prevents local file URL testing; it was not bypassed. Native Windows/browser verification remains pending.
