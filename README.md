## Цель проекта — прочитать перед продолжением

Приложение нужно для **калькуляторов по готовым дампам EEPROM/Flash**.
Чтение и запись микросхем пользователь выполняет через MultiProg.
Аппаратные функции iProg, управление адаптерами и подключение к процессорам
намеренно исключены; их отсутствие не является недоделкой.
Подробная постановка задачи и честное разделение «поддерживается»/«проверено»:
[PROJECT_SCOPE.md](https://github.com/naslednik3501/cal-workbench/blob/main/PROJECT_SCOPE.md).

Текущий результат: [DELIVERY-2026-11-03.md](DELIVERY-2026-11-03.md). В каталоге 15 057 разных CAL: точные повторы объединены, Sportage добавлен, оригинальные картинки восстановлены для 288 калькуляторов. Поддержка всех CAL пока не завершена.

## Как собрать

Требуется Python 3.9+; внешние Python-пакеты и npm-зависимости для сборки не нужны.

```sh
python3 build_static.py
```

Команда проверяет SHA-256 и размеры оригинальных файлов по MANIFEST.json и копирует только веб-ресурсы в `dist/`. Она пересоздаёт только `dist/`. После будущих изменений приложения необходимо осознанно обновить исходный манифест: проверка не должна скрывать изменения.

Проверки, воспроизводимые без личных дампов:

```sh
node tests/test_catalog.js
node tests/test_catalog_store.js
```

Без личных BIN также работают test_source, test_preparation, test_polo, test_sportage, test_scope, test_catalog_dedup, test_binary_events и test_text_variants. Браузерные test_scope_browser, test_catalog_dedup_browser и test_release_browser требуют Playwright/Chromium и localhost URL. Старые test_engine, test_browser и test_ui_state требуют личных BIN из `tests/README.md`.

## GitHub Pages

Публикация: Settings → Pages → Deploy from a branch → `main` → `/(root)`.
Корневой `.nojekyll` отключает обработку Jekyll; HTML/CSS/JavaScript публикуются напрямую.
После сохранения изменений в `main` GitHub автоматически обновляет сайт.

Сборка `dist/` нужна только для переноса на другой статический хостинг.
Исходные ZIP и личные BIN-дампы в репозиторий не входят.

Документация: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Поведение онлайн-версии

BIN обрабатывается в браузере. CSP исходной страницы запрещает сетевые соединения приложения (`connect-src 'none'`). Импортированные CAL сохраняются в IndexedDB текущего браузера, профиля и адреса сайта. Переход с локального файла на HTTPS не переносит прежний импорт; нужен повторный импорт исходных CAL. Автоматической синхронизации между устройствами нет.

Встроенные CAL загружаются целиком; восстановленные изображения (около 20 MB суммарно) загружаются при открытии соответствующей формы; первая загрузка зависит от сети и сжатия хостинга. В каталоге сохранены и исходные ресурсы, не являющиеся CAL, включая EXE как данные; Windows-код приложение не запускает. Сайт и встроенный каталог доступны всем посетителям, в соответствии с выбранным публичным размещением.

Подробности проверки и ограничения — в `AUDIT-2026-11-01.md`. Успех статического разбора не подтверждает результат на реальном блоке.

Первоначальные архивы, статус постоянного хранилища и инструкция для следующих чатов: [SOURCE_STORAGE.md](SOURCE_STORAGE.md).
