выбраны только записи с ошибкой «Исходный текст, внешняя программа или другой

Исходные байты взяты из уже имеющихся catalog blobs и все сверены по SHA-256;

Короткий реестр по каждому полному SHA: путь, формат, назначение, наличие

`null` в containsBinCalculation означает, что операция за непрочитанной

## Этап 2 — проверка существующих оболочек

Проверены ограниченные однородные группы, до реализации нового языка:

1. Для восьми hex-файлов снят только текстовый заголовок. Для serial-варианта
   также отдельно сняты явные строки комментариев `!`. Длина и кодирование
   остаются несовместимыми с существующим CAL decoder.
2. Исследовательский кандидат «32 байта данных + два служебных байта на строку»:
   удаление последних двух байтов каждой строки, а также вариант без первого
   блока не проходят существующую проверку кодирования/CRC. Проверка CRC-16
   0x1021 по сырым первым 32 байтам строк также не совпала ни у одной строки
   восьми файлов ни с LE, ни с BE двумя последними байтами. Поэтому считать их
   обычной CRC или молча выбросить нельзя. **Эти преобразования не включены в
   runtime**; оригинальные байты сохранены.
3. По двум текстовым launcher полное содержимое — `OnShow { Execute(path,args) }`.
   Оба передают `"1 2 3 4"`, но это не описание алгоритма. Отсутствие Form/Size
   не является единственной причиной блокировки: зависимость — внешняя программа.
   Не добавлены произвольный Execute, запуск EXE или фиктивный пустой OnShow.
4. Четыре уже поддерживаемых одноимённых Bombardier проверены выборочно по SHA
   и parse; это другие оригиналы с образами 832/1088/1024/832 байта. Совпадение
   названия не доказывает совпадение алгоритма с этими четырьмя упакованными
   файлами. Подмена SHA и выдача существующей поддержки за новый перенос запрещены.

Проверяемые байтовые факты/результаты кандидатов:
[T-007-byte-evidence-2026-11-04.json](T-007-byte-evidence-2026-11-04.json).
Воспроизведение: `node tools/analyze_t007_formats.js`.

## Нативные программы — не исключены из области

Оба файла имеют PE\0\0, machine 0x14c и VERSIONINFO:
`CompanyName=MANEX`, `ProductName=Audi VDO Crypto calculator`,
`InternalName=VDO Crypto`, FileVersion=2.6.0.0. Это подтверждённые программы
калькулятора, а не произвольные ненужные EXE.

У 1835b7bd… ресурс TFORM1 начинается с TPF0 и содержит открытие/сохранение
зашифрованного и расшифрованного файла, Login/ImmoID/Set_KM. В Delphi method
таблице найдены Make_Decrypt (VA 0x44F454), обработчики открытия и сохранения и
Set_KM_buttonClick (0x451A58). Статический участок Make_Decrypt ссылается на
преобразование 0x44F2C0, цикл по 1024 словам, XOR и таблицу 0x4549EC.
Следовательно, полезный расчёт по BIN имеется. Это ещё не доказательство полной
семантики всех подпрограмм, формата BIN или обратимости всей программы.

У f8607236… CODE raw=125952 против virtual=372736, entryRVA=0x1000 с loader,
нулевые payload ресурсов при сохранённых именах. Требуется статическое
восстановление защищённого содержимого. Одинаковые VERSIONINFO двух программ
не доказывают одинаковые алгоритмы; они не объединялись.

Доказательства, шесть адресов методов и точные байты участка Make_Decrypt:
[T-007-native-evidence-2026-11-04.json](T-007-native-evidence-2026-11-04.json).
Воспроизведение: `python tools/analyze_t007_native.py --dir /path/to/12-originals`
(исследовательская зависимость pefile; оригиналы SHA.cal из catalog blobs).
**EXE и инструкции из них не исполнялись**, использован только статический PE
разбор. Программы не обёрнуты в исполняемую Windows-среду на сайте.

## Что нужно для продолжения

- Восемь hex-оригиналов: доказать framing, проверку целостности и декодирование
  обеих отмеченных упаковок. Нужны эталонный decoder исходного хоста/спецификация
  либо расшифрованный соответствующий оригинал с доказанной связью и результатами.
  После этого проверить, совпадают ли форма, события и операции с нашим runtime.
  Несовпадение потребует отдельного ограниченного переноса формата, а не попытки
  сделать успешным parse удалением неизвестных байтов. По серийному калькулятору
  затем отдельно определить, имеет ли он операции по BIN.
- 1835b7bd…: отдельный нативный порт имеющихся подпрограмм. Точное место начала —
  Make_Decrypt VA 0x44F454 → 0x44F2C0, таблица 0x4549EC, затем обратное шифрование,
  определение crypto metadata/формата и границ файла, PIN/ImmoID/KM. Необходимы
  независимые входные/выходные векторы или авторская спецификация. Часть кода уже
  доступна статически; не утверждается, что исходный EXE отсутствует.
- f8607236…: сначала статически восстановить защищённый PE и установить точную
  связь с алгоритмом/вариантом; затем ограниченный порт BIN-операций с векторами.
- Два Execute launcher: только после доказанного порта точной зависимости.
  Указанные пути `..\\Calculators\\Dashboard\\CRYPTO\\...` не совпадают с путями
  двух CAL-PE в каталоге; сходное имя не является доказанной привязкой.

Такой объём требует новой реализации декодеров/нативных алгоритмов. По прямому
ограничению владельца большой перенос нового языка/Windows-интерпретатора не
начат. Все остальные файлы группы обработаны независимо; готовых групп для
разблокировки в имеющемся движке не обнаружено. Это **проверенный ограниченный
результат 0/12**, а не утверждение о принципиальной невозможности переноса.
