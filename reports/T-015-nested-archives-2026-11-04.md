## Итог в одну строку

Контейнеров найдено и учтено **13** (12 разных RAR и один ODT-ZIP), необработанных
или заблокированных нет. Новых уникальных CAL — **0**, добавленных изображений — **0**,
привязок не доказано — **0**. Приложение уже содержит все уникальные байты CAL пяти ZIP,
поэтому вложенные архивы не добавляют ни калькуляторов, ни ресурсов.

По остатку T-010 вывод сформулирован узко, по факту применённых способов поиска:

- у **118** неоднозначных ссылок кандидаты в прямых архивах **существуют** — они уже

- у **1 309** ссылок без источника соответствий не найдено **применёнными способами

  CAL). Это не доказательство отсутствия изображения: файл с другим именем или без
  совпадающего пути такими способами не находится. Формулировки вида «изображения нет
  во всех источниках» здесь не используются.

## Как искали

1. Полный перебор 23 678 уникальных объектов хранилища по сигнатурам `PK\x03\x04`
   (ZIP и производные), `Rar!\x1a\x07`, 7z, bzip2, gzip, xz, tar. Читались первые
   байты распакованного содержимого, поэтому переименованный контейнер тоже был бы найден.
2. Найденные контейнеры получены выборочно из объектов хранилища (напрямую или из `chunks`)
   и распакованы libarchive как данные.
3. Каждый вложенный файл сверен по SHA-256 с каталогом приложения и с индексом хранилища.
4. Остаток T-010 сверен с содержимым контейнеров тремя способами: по имени файла,
   по полному целевому пути (`папка CAL` + ссылка и `Calculators/Pictures/` + ссылка)
   и по исходной папке каждого CAL в хранилище.
5. Дополнительно выполнен поиск текста CAL по содержимому объектов независимо от
   расширения: 1 488 объектов, из них 1 487 `.cal` и один `.123` (уже в каталоге).
   Расчётных файлов под чужим расширением нет.

## Воспроизводимость

Скрипт перебора и сопоставления сохранён в репозитории:
[tools/t015_nested_archives.py](../tools/t015_nested_archives.py). Нужны локальная копия
закрытого хранилища (commit `ab589e2…`) и `bsdtar` (libarchive) с поддержкой RAR;
программы из архивов не запускаются, контейнеры распаковываются как данные.

    python tools/t015_nested_archives.py all --store ../iprocal-sources --work /tmp/t015

Шаги по отдельности: `scan`, `extract`, `classify`, `match`. Контрольный запуск на этой
машине воспроизвёл те же числа: 23 678 объектов, 13 контейнеров (12 RAR + ODT), 462 файла,
324 уникальных SHA-256, 0 контейнеров второго уровня, 0 новых CAL, 97 новых изображений,
0 соответствий по внутреннему пути, точному целевому пути и исходной папке CAL.
Ограничения: приватное хранилище и `bsdtar` обязательны, промежуточные JSON пишутся только
в `--work` и в репозиторий не попадают; `iProgPro.rar` распаковывается с предупреждением
`bsdtar` по `iProgPro.exe` (код возврата 1), сам файл извлекается и сравнивается.

## Изображения

В контейнерах **97** новых уникальных изображений и 3 уже имеющихся (тот же SHA):

- 86 иконок панели iProgPro в `Toolbars/*` (`0.png`, `1.png`, `bmw.png`, `pastedpic_*`),
  одни и те же байты в `iProgPro.rar` и в `iProgPro69.rar`;
- 11 файлов в папках с расчётными материалами: 5 уникальных кадров Mazda 57K30
  (`0–4.png`, `SRS_MAZDA_6_CX5_IFINEON.png`, `SRS_MAZDA_6_IFINEON_R_W.png` — 7 файлов),
  2 фото Honda MB91F06x (`Honda060.jpg`, `Honda061.jpg`), `Dash_Connection.jpg` и
  `Info.png` Камаза, 2 фото блока Pointer (`377909603-a.png`,
  `377 909 603-A  MC68HC11E9.png`);
- 3 файла (`vw.png`, `hyundai.png`, `grantasrs.png`) уже есть в приложении по тому же SHA.

Ни один из них не добавлен, потому что доказанной связи с конкретным CAL нет:

- у **118** неоднозначных ссылок остатка T-010 кандидаты в прямых архивах существуют и уже
  перечислены в поле `candidates` (одинаковое имя в разных папках, разные SHA-256). Сверка
  с контейнерами не дала **ни одного дополнительного соответствия**: по внутреннему пути,
  по точному целевому пути и по исходной папке CAL — 0 совпадений;
- у **1 309** ссылок без источника соответствий не найдено применёнными способами поиска
  (индекс имён прямых архивов, базовое имя, точный целевой путь, исходная папка CAL).
  Вывод ограничен этим: отсутствие совпадения имени не доказывает, что изображения нет под
  другим именем; поиск по содержимому изображений не выполнялся, это вне рамок T-015;
- наивное сравнение только по базовому имени по всем 462 файлам контейнеров даёт 106
  совпадений на 12 ссылках. Все они указывают на иконки панели iProgPro (`0.png`, `1.png`,
  `3.png` …) и кадры программ — совпадение имени без пути и контекста, поэтому такие
  пары не считаются соответствием и не используются как кандидаты;
- кадры Mazda принадлежат программе, а не CAL: `SRS_MAZDA_6_IFINEON_R_W.ipr` ссылается
  на `0.png` и является аппаратной программой чтения/записи блока SRS;
- иконки iProgPro — оформление панели программы, к расчётам дампа отношения не имеют.

## Две версии iProgPro

`iProgPro.rar` и `iProgPro69.rar` содержат одинаковый набор членов и одинаковые иконки,
`hitag2.cal`, `lua`-скрипты и базы. Отличаются только `iProgPro.exe` и `russian.lng`,
то есть это две версии самой программы. Ничего не объединено и не удалено; для задачи
это не ресурсы калькулятора.
